# 即变模板范围与分类标准

## 1. 文档目的

本文用于定义「即变」第一阶段可以制作、上架和验证的模板范围。

模板范围的目标不是把所有可能性一次性做完，而是帮助产品、运营和开发判断：

- 什么样的玩法可以算作即变模板。
- 第一版模板应该覆盖哪些类别。
- 哪些模板优先做。
- 哪些模板需要谨慎做。
- 哪些模板第一阶段不做。

## 2. 模板定义

即变第一阶段只做「人物图片结果型模板」。

一个模板必须满足以下条件：

- 用户上传一张人物照片后，可以生成一个明确的人物图片结果。
- 结果可以用于头像、写真、朋友圈、小红书 / 抖音封面、社交展示面或娱乐分享。
- 模板有清晰的封面、标题、示例图、用途说明和风险等级。
- 模板不依赖用户自由输入 Prompt。
- 模板由平台预先配置 Prompt / Workflow / 模型参数。
- 模板结果应该具备保存、分享或发布价值。

即变模板不是简单滤镜，也不是通用 AI 生图入口。用户侧感知应该是「选一个案例，把自己变成类似结果」。

## 3. 第一阶段模板边界

第一阶段优先支持：

- 单人图片。
- 单张图片输入。
- 单张结果输出。
- 固定模板生成。
- 面向普通用户的娱乐、形象、社交展示结果。

第一阶段暂不优先支持：

- 多人复杂合成。
- 一次生成整套写真。
- 视频生成。
- 用户自由 Prompt。
- 严肃证件用途。
- 高风险身份替换。

后续可以扩展为套图、视频、多人关系图、用户自定义玩法，但这些不作为第一版 MVP 范围。

## 4. 五大模板类别

第一版模板按五个大类组织：

| 类别 | 核心目的 | 用户理解方式 |
| --- | --- | --- |
| 头像类 | 快速生成可替换头像的结果 | 换一个更好看的头像 |
| 写真类 | 生成有拍摄感的人像照片 | 低成本拍一张好看的写真 |
| 风格变换类 | 将原图变成某种审美风格 | 把照片变成某种流行风格 |
| 角色类 | 把用户变成某种角色设定 | 看看自己变成某个角色是什么样 |
| 场景类 | 把用户放进特定生活、旅行或节日场景 | 生成一张像真的去过或经历过的照片 |

这五类是内部模板生产分类，不一定要求在用户侧完全原样展示。用户侧可以根据转化需要使用「热门」「风格」「头像」「写真」「角色」等更短入口。

## 5. 头像类

### 定义

头像类模板用于生成适合社交账号、微信头像、小红书头像、情侣头像、职业头像等场景的人物头像结果。

### 适合做的方向

- 氛围感头像
- 小红书头像
- 高级感头像
- 甜酷头像
- 职业头像
- 情侣头像
- 动漫头像
- 节日头像
- 轻商务头像
- 社交软件头像

### 判断标准

头像类模板应该满足：

- 人脸清晰。
- 构图适合裁剪成头像。
- 背景不喧宾夺主。
- 用户能直接用于社交平台。
- 标题要明确表达头像用途。

### 示例标题

| 模板标题 | 用途 |
| --- | --- |
| 小红书氛围头像 | 适合小红书、朋友圈头像 |
| 甜酷女生头像 | 适合年轻女性社交头像 |
| 轻商务头像 | 适合职场、轻商务展示 |
| 动漫感头像 | 适合娱乐化头像 |
| 情侣头像半身照 | 适合情侣社交头像 |

## 6. 写真类

### 定义

写真类模板用于生成具备拍摄感、摄影感、成片感的人像图片。

### 适合做的方向

- 古风写真
- 轻写真
- 街拍写真
- 胶片写真
- 韩系写真
- 小红书写真
- 赛博写真
- 复古写真
- 生日写真
- 节日写真

### 判断标准

写真类模板应该满足：

- 画面像真实拍摄或专业修图结果。
- 有明确服装、光线、背景或氛围。
- 结果适合保存、发朋友圈或发小红书。
- 不以擦边、暴露或高风险性感表达作为卖点。

### 示例标题

| 模板标题 | 用途 |
| --- | --- |
| 古风轻写真 | 适合朋友圈和小红书发布 |
| 城市街拍写真 | 适合生活方式展示 |
| 胶片氛围写真 | 适合复古风内容 |
| 韩系清透写真 | 适合头像和朋友圈 |
| 赛博夜景写真 | 适合强视觉冲击内容 |

## 7. 风格变换类

### 定义

风格变换类模板用于把用户原图转换成某种明确审美风格。它不一定改变用户身份或角色，而是改变画面质感、色调、妆造、摄影语言和社交平台审美。

这是即变第一阶段非常重要的模板板块，因为用户不一定想变成某个角色，但经常想知道「自己的照片换一种风格会不会更好看」。

### 适合做的方向

- 小红书感
- 甜酷风
- 港风
- 胶片风
- 韩系风
- 日系风
- 复古风
- 赛博风
- 清冷感
- 氛围感
- 高级感
- 男友感 / 女友感

### 判断标准

风格变换类模板应该满足：

- 风格名称用户能理解。
- 改变足够明显，但仍保留用户本人特征。
- 结果适合发布，不只是滤镜效果。
- 示例图必须强，因为用户主要靠示例理解风格。

### 示例标题

| 模板标题 | 用途 |
| --- | --- |
| 小红书网感照片 | 适合朋友圈和小红书内容 |
| 港风胶片感 | 适合复古头像和写真 |
| 甜酷少女感 | 适合年轻女性社交展示 |
| 清冷高级感 | 适合头像、封面和展示面 |
| 赛博氛围感 | 适合强视觉冲击玩法 |

## 8. 角色类

### 定义

角色类模板用于把用户变成某种虚构、风格化或设定感较强的人物角色。

角色类的核心是「代入感」和「想象力」，不是单纯变好看。

### 适合做的方向

- 古风角色
- 赛博角色
- 白发角色
- 幻想角色
- 武侠角色
- 游戏感角色
- 职业角色
- 校园角色
- 电影感角色
- 二次元角色

### 判断标准

角色类模板应该满足：

- 角色设定明确。
- 视觉变化足够强。
- 用户可以一眼理解变成了什么。
- 不指向真实公众人物或明星。
- 不使用「变成某某明星」作为卖点。

### 示例标题

| 模板标题 | 用途 |
| --- | --- |
| 白发赛博少女 | 适合强视觉角色化玩法 |
| 古风侠客 | 适合古风角色图 |
| 未来机能战士 | 适合科幻角色图 |
| 魔法学院学生 | 适合轻幻想角色 |
| 电影感女主 | 适合角色化写真 |

## 9. 场景类

### 定义

场景类模板用于把用户放入一个具体生活、旅行、节日或故事场景中，让结果像一张「真的可以发出去」的照片。

场景类的重点不是只换背景，而是生成一个有完整氛围、姿态、服装和环境关系的成品图。

### 适合做的方向

- 旅行打卡
- 城市街拍
- 海边度假
- 雪景写真
- 节日氛围
- 婚纱 / 婚礼回忆
- 生日氛围
- 咖啡馆生活照
- 音乐节现场
- 朋友圈出片场景

### 判断标准

场景类模板应该满足：

- 场景明确。
- 用户能理解这张图可以发在哪里。
- 结果像完整照片，而不是简单贴人换背景。
- 不制造明显欺骗性身份、地点或事件。
- 高风险真实事件、政治、灾害、医疗等场景不做。

### 示例标题

| 模板标题 | 用途 |
| --- | --- |
| 海边度假出片 | 适合朋友圈生活照 |
| 东京街头旅行照 | 适合旅行感内容 |
| 雪景氛围写真 | 适合冬季玩法 |
| 咖啡馆生活照 | 适合日常社交展示 |
| 复古婚纱回忆 | 适合补足纪念照需求 |

## 10. 首批 50 个模板配比

第一版建议 50 个模板按以下比例制作：

| 类别 | 数量 | 原因 |
| --- | ---: | --- |
| 头像类 | 10 | 高频、易分享、易理解 |
| 写真类 | 12 | 结果感强，适合小红书和朋友圈 |
| 风格变换类 | 10 | 覆盖最广，适合快速测试审美偏好 |
| 角色类 | 10 | 娱乐性强，适合传播和点击 |
| 场景类 | 8 | 适合打造差异化，但单个模板制作成本更高 |

这个配比不是固定规则，可以根据真实数据调整。

调整依据：

- 点击率高的类别增加模板。
- 上传率高的类别增加模板。
- 保存率高的类别优先优化。
- 付费率高的类别进入重点运营。
- 高风险或结果不稳定的类别减少上新。

## 11. 模板准入标准

一个模板准备上线前，需要满足以下标准：

- 标题清楚，用户一眼知道会生成什么。
- 封面有吸引力，能体现最终结果。
- 示例图质量稳定，不只是一张偶然好图。
- 结果用途明确，可以保存、分享或发布。
- 风险等级明确。
- 生成成本可控。
- 失败率可接受。
- 不依赖用户自由输入。
- 不违反第一阶段风控边界。

如果一个模板只能证明「技术能做」，但不能证明「用户想用」，不应该优先进入第一批。

## 12. 谨慎制作范围

以下模板不是绝对禁止，但第一阶段需要谨慎：

- 婚纱 / 婚礼类：可以做纪念和氛围，不要暗示真实事件伪造。
- 职业类：可以做轻商务、职业形象，不要做证件、资质、执业身份伪造。
- 旅行类：可以做氛围图，不要强调真实到访证明。
- 情侣类：需要避免未经授权使用他人照片。
- 强妆造类：需要避免结果过度失真导致用户不满意。
- 老年回忆类：情绪价值强，但需要注意隐私和肖像授权。

## 13. 禁止制作范围

第一阶段不做以下模板：

- 明星脸 / 名人脸。
- 政治人物、宗教人物、公众人物相关模板。
- 未成年人相关人物生成模板。
- 强换脸或真实身份替换。
- 情色、擦边、暴露、性暗示模板。
- 证件照、学历证明、职业资质等严肃用途。
- 医疗、法律、金融等高信任场景伪造。
- 灾害、犯罪、冲突等高风险事件场景。
- 用户自由 Prompt 生图。
- 多人复杂合成。
- 视频生成。

禁止类模板不进入第一版，即使短期点击率可能高，也不作为 MVP 验证方向。

## 14. 模板字段标准

每个模板至少需要配置以下字段：

| 字段 | 说明 |
| --- | --- |
| 模板名称 | 用户可见标题 |
| 所属类别 | 头像类 / 写真类 / 风格变换类 / 角色类 / 场景类 |
| 封面图 | 用户浏览时看到的主图 |
| 示例图 | 展示生成前后或生成效果 |
| 用途说明 | 告诉用户适合拿来做什么 |
| Prompt / Workflow | 内部配置，不对用户展示 |
| 输入要求 | 单人照、半身照、正脸照等 |
| 输出比例 | 1:1、3:4、4:5、9:16 等 |
| 价格 / 点数 | 单次生成消耗 |
| 风险等级 | 低 / 中 / 高 |
| 排序权重 | 用于首页和分类排序 |
| 上下架状态 | 草稿 / 上架 / 下架 |

## 15. 用户侧分类建议

内部分类是五类，但用户侧入口要更短、更容易理解。

首页 Tab 可以使用：

- 热门
- 风格
- 头像
- 写真
- 角色

其中「场景类」可以根据具体模板进入热门、风格或专题活动，不一定在首页单独做一级 Tab。

底部导航建议保持：

- 首页
- 风格
- 我的

第一版不要把入口做得太多，避免用户不知道从哪里开始。

## 16. 后续扩展方向

第一阶段验证成立后，可以扩展：

- 一次生成一套图。
- 模板合集。
- 节日专题。
- 用户作品广场。
- 热点玩法商店。
- 自动化模板生产 Agent 系统。
- 多模型源头自动路由。
- 海外审美模板。

这些能力不作为第一版上线前置条件，避免过早扩复杂度。
