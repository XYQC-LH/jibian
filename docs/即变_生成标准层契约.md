# 即变生成标准层契约

更新时间：2026年08月01日  
适用范围：业务层创建生成任务、后端 Worker、source adapter、第三方模型源 API。

## 定位

生成标准层是业务层和第三方源头 API 之间的通讯标准，也是一层防腐层。

业务层不能直接拼第三方 API 请求字段，第三方 API 字段也不能反向污染业务模型。业务层先转换成 `StandardGenerateInput`，再由具体 source adapter 把标准字段转换成实际源头 API 的请求字段。

```text
业务层字段
  -> StandardGenerateInput
  -> SourceAdapter
  -> 第三方源头 API 字段

第三方源头 API 响应
  -> SourceAdapter 转换并完成必要转存
  -> StandardGenerateOutput
  -> 业务层更新 task / source_run
```

## 核心原则

- 业务层只依赖标准层，不依赖任何第三方源头 API 字段。
- source adapter 只接收标准输入，并只返回标准输出。
- 标准层只定义即变业务真正稳定需要的字段。
- 标准层没有声明的字段，不允许业务层透传给源头 API。
- 源头私有字段由 source adapter 内部通过默认值、服务端配置或代码常量解决。
- 不同源头字段名不同不影响标准层命名，例如源头叫 `text`、`prompt_text`、`description`，标准层都叫 `prompt`。

## 标准输入

标准输入只定义三类字段：提示词、图片、比例。

| 标准字段 | 类型 | 必填 | 业务来源 | 含义 |
|---|---|---:|---|---|
| `prompt` | `string` | 是 | `templates.prompt` | 后端组装完成后提交给源头的提示词。 |
| `imageUrl` | `string` | 是 | `tasks.input_asset_id -> assets` | 用户上传原图的可访问地址。 |
| `ratio` | `GenerateRatio` | 是 | 用户端创建 task 时提交 | 本次生成希望使用的图片比例。 |

```ts
export type GenerateRatio = "auto" | "1:1" | "3:4" | "4:3" | "9:16" | "16:9";

export type StandardGenerateInput = Readonly<{
  prompt: string;
  imageUrl: string;
  ratio: GenerateRatio;
}>;
```

## 标准输出

标准输出只定义业务层真正需要接收的结果。源头返回 URL、字段名差异、原始响应解析、结果图下载和对象存储转存，都由 source adapter 或标准层内部完成，业务层不接触第三方 API 响应结构。

| 标准字段 | 类型 | 必填 | 含义 |
|---|---|---:|---|
| `ok` | `boolean` | 是 | 标识标准层处理成功或失败。 |
| `assetId` | `string` | 成功时必填 | 标准层已转存后的内部资产 ID。 |
| `errorMessage` | `string` | 失败时必填 | 标准层处理失败时给业务层展示或记录的错误说明。 |

```ts
export type StandardGenerateOutput = Readonly<
  | {
      ok: true;
      assetId: string;
    }
  | {
      ok: false;
      errorMessage: string;
    }
>;
```

## Adapter 接口

所有源头都必须实现统一 adapter 接口。

```ts
export interface SourceAdapter {
  readonly sourceId: string;
  generate(input: StandardGenerateInput): Promise<StandardGenerateOutput>;
}
```

adapter 的职责：

- 把 `StandardGenerateInput` 转换成源头 API 请求字段。
- 把源头 API 响应转换成 `StandardGenerateOutput`。
- 处理源头私有参数、默认值、字段命名差异和鉴权细节。
- 成功时把源头结果图转存为内部 asset，并只把 `assetId` 返回给业务层。
- 失败时把源头错误归一化成 `errorMessage` 返回给业务层。

adapter 不负责：

- 创建 task。
- 扣费或退款。
- 内容审核。
- 创建 user creation。
- 直接更新业务主表。

## 字段映射示例

不同源头只能在 adapter 内部做字段映射。

```ts
function toFooSourcePayload(input: StandardGenerateInput) {
  return {
    text: input.prompt,
    image_url: input.imageUrl,
    ratio: input.ratio,
  };
}

function toBarSourcePayload(input: StandardGenerateInput) {
  return {
    prompt: input.prompt,
    initImage: input.imageUrl,
    aspect_ratio: input.ratio,
  };
}
```

业务层禁止这样做：

```ts
// 禁止：业务层直接拼第三方 API 字段
const payload = {
  text: template.prompt,
  image_url: imageUrl,
  aspect_ratio: ratio,
};
```

业务层必须这样做：

```ts
const input: StandardGenerateInput = {
  prompt: template.prompt,
  imageUrl,
  ratio,
};

const output = await sourceAdapter.generate(input);
```

业务层接收输出时也只能处理标准字段：

```ts
if (output.ok) {
  await taskRepository.markSucceeded(taskId, output.assetId);
} else {
  await taskRepository.markFailed(taskId, output.errorMessage);
}
```

## 前端对齐

用户端不直接提交完整标准输入。前端只提交用户可选择的业务字段：

```json
{
  "template_id": "tpl_001",
  "input_asset_id": "asset_001",
  "ratio": "1:1"
}
```

后端创建 task 后补齐标准输入：

- 从 `templates.prompt` 取得 `prompt`。
- 从 `assets.storage_key` 生成 `imageUrl`。
- 使用前端提交的 `ratio`。

## 不进入标准层的字段

以下字段不进入标准输入：

- `taskId`、`userId`、`templateId`。
- 第三方 API Key、鉴权头、签名参数。
- 第三方私有参数，例如 seed、风格强度、cfg scale、scheduler。
- 第三方回调地址、webhook secret、异步轮询间隔。
- 原始请求体和原始响应体。
- 第三方返回的图片 URL、临时文件 URL、下载地址。

这些内容由业务上下文、source adapter、服务端配置或 `source_runs` 处理。
