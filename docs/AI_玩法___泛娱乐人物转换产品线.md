# AI 玩法 / 泛娱乐人物转换产品线

产品名称：即变

## 0. 项目定位

### 这个产品是什么

即变是一个结果型 AI 娱乐产品。

用户在小程序里浏览已经做好的玩法模板，点击尝试，上传一张自己的照片，系统生成一张可保存、可分享、可发布的效果图片。

典型结果包括：

- 头像
- 写真
- 角色化图片
- 变帅 / 变美图
- 小红书 / 抖音封面人物图
- 朋友圈出片
- 社交主图
- 轻商务形象
- 男友感 / 女友感氛围图
- 街拍、小红书感照片
- 普通自拍改造
- 过去需要 PS 或复杂修图才能实现的视觉效果

产品核心不是让用户学习 AI、写 Prompt 或调参数，而是利用模型的图片编辑能力，把用户照片直接转化成一个可用的成品结果。

第一阶段重点服务愿意为酷炫效果、头像、写真、朋友圈展示和社交展示面付费的年轻用户，尤其是 14-35 岁年轻女性用户。

### 这个产品的使用流程

核心流程：

1. 用户进入小程序。
2. 用户看到丰富的模板、特效或配方。
3. 用户点击某个玩法模板。
4. 系统引导用户选择并上传一张图片。
5. 用户开始生成。
6. 系统输出同款效果图片。
7. 用户保存、分享、发布或继续生成。

示例玩法：

- 小红书网感特效：用户上传自己的照片后，直接生成同款小红书风格人物图。
- 古风写真：用户上传自拍后，生成古风写真效果。
- 角色化图片：用户上传照片后，生成白发少女、赛博角色、古风角色等效果。

核心逻辑是平台内部预先配置大量成熟模板，用户只需要浏览内容、选择玩法、上传图片，就能得到自己的成品效果。

### 第一阶段目标

第一阶段不是做大平台，而是验证用户是否愿意完成以下闭环：

- 上传图片
- 选择模板
- 生成结果
- 保存结果
- 分享结果
- 为结果付费

第一阶段只验证小闭环，不追求完整平台。当前优先推进微信小程序，Web 主要作为展示页或后台管理入口，暂不优先做独立 App。

### 最重要的判断标准

两周到一个月内，能否跑通真实用户和真实付费闭环。

如果没有真实用户、没有付费、没有渠道反馈，就不应该继续扩复杂架构。

### 模板类型划分

模板类型划分不一定全部面向用户展示，但内部制作模板时需要明确分类。

当前可覆盖的模板方向：

1. 个人写真：古风写真、赛博写真、轻写真、街拍写真。
2. 朋友圈展示：适合发朋友圈、社交软件头像、生活状态展示。
3. 角色化效果：白发少女、古风角色、赛博角色、职业角色、幻想角色。
4. 旅行场景：生成像真实到某个城市或景点旅行过的照片。
5. 风格化玩法：小红书感、港风、胶片、甜酷、氛围感等。
6. 套图扩展：第一阶段服务单张图片，后续可以扩展为一次生成一组图。
7. 特殊人群需求：例如为老年人补足年轻时没有机会拍摄的婚纱照、婚礼照等影像需求。

## 1. 用户是谁

### 第一批用户是谁

第一批用户从 C 端社交展示人群切入，核心形态优先是微信小程序。

如果小程序验证效果不错，后续再考虑 App、Web、海外版本等形态。

产品依托强社交传播和便捷生成效果，第一阶段不适合把 Web 作为主要 C 端入口。Web 可以先承担官网、投放承接页和管理员后台。

### 是广泛人群还是细分人群

即变面向广泛用户开放，但第一阶段需要重点关注细分人群。

核心目标用户：

- 14-35 岁年轻女性用户
- 对头像、写真、朋友圈、小红书展示有需求的人
- 愿意为好看、新鲜、可分享的视觉效果付费的人

产品可以服务更广泛人群，但第一阶段不应发散，需要先抓住最可能上传、分享和付费的用户。

### 用户核心需求是什么

用户不是单纯「玩一下」，而是希望生成能实际使用的图片结果。

核心需求包括：

- 生成可以当头像的图片。
- 生成可以发朋友圈的图片。
- 生成可以发小红书或抖音的封面人物图。
- 生成能优化社交展示面的照片。
- 低成本获得一张过去需要拍摄、修图或 PS 才能得到的图片。
- 满足好奇心、虚荣心、发布欲和社交展示需求。

结果越能被用户拿去展示、吸引别人、做内容封面，需求强度越高。

### 用户主要出现在哪些平台

第一阶段重点关注：

- 小红书
- 抖音
- 朋友圈
- 闲鱼
- 社交软件头像场景

渠道特点：

- 小红书适合展示前后对比、头像、写真和氛围感案例。
- 抖音适合展示变化过程和强视觉冲击。
- 闲鱼适合测试低价付费需求。
- 朋友圈和社群适合做自然传播和邀请裂变。

## 2. 需求强度

### 这是强需求还是弱需求

即变不是刚需，属于中需求和弱需求混合。

需求强度拆分：

- 纯娱乐玩法偏弱。
- 头像、写真、社交展示面、内容封面偏中等。
- 服务内容创作、账号包装和展示面优化的场景更强。

所以产品不能只表达「AI 玩法」，而要把玩法绑定到具体用途。

### 用户为什么可能付费

如果结果真的能拿去发头像、朋友圈、小红书、社交展示面，用户就有付费理由。

用户不是为 AI 技术付费，而是为以下结果付费：

- 更好看的自己
- 更强的社交展示面
- 更能发出去的内容
- 更低成本的写真或形象照
- 更有新鲜感和传播性的视觉结果

### 用户为什么可能不付费

用户不付费的主要原因：

- 只是觉得新鲜，生成一下看看。
- 结果不够好看。
- 结果不稳定。
- 结果不能发布或不能当头像。
- 用户生成前不确定效果，不愿意先付费。

### 怎么提高需求强度

提高需求强度的关键是把玩法绑定具体用途，而不是只说 AI 玩法。

推荐表达方向：

- 做头像
- 做展示面
- 做朋友圈图
- 做小红书封面
- 做社交软件照片
- 做轻写真
- 做节日图

结果越具体，用户越容易理解为什么要生成，也越容易付费。

### 还需要验证的问题

- 用户愿意为单张图付多少钱？
- 用户愿意为一套图付多少钱？
- 用户是否愿意为高清下载、去水印、多次重生成付费？
- 用户是否接受积分包和会员模式？
- 用户是否会复购？
- 用户是否愿意主动分享给朋友？

如果效果足够好，单次结果可以测试 0.5-9.9 元区间，长期可重点验证积分包和会员权益。

## 3. 竞品与差异

### 这个市场是不是蓝海

这个市场看似红海，但仍有切入机会。

美图、醒图、剪映、Canva、CapCut、Remini、AI 写真小程序和各种头像生成工具都在做相关能力，用户对修图、写真、头像和模板工具并不陌生。

但传统工具更多停留在修图、滤镜、剪辑、排版或简单特效，用户仍然需要手动操作。即变要做的是直接面向结果的模板生成：用户上传图片后，系统直接输出一个已经包装好的成品效果。

机会不在于「我也能生成」，而在于：

- 更垂直的玩法模板。
- 更快追热点。
- 更懂中文社交平台审美。
- 更强的结果包装。
- 更低成本、更快生成。
- 更适合普通人的社交展示结果。

### 你的机会在哪里

小团队不适合和大厂拼完整功能，适合拼细分场景、速度、包装和内容分发。

即变的机会是把模板做成一个可持续生产、可快速上新、可追热点的系统。前期可以人工或半自动制作模板，后期再考虑自动化产出模板的 Agent 系统。

这个模板生产能力后续不只服务即变，也可以服务基于模板构建的其他产品。

### 用户为什么不用竞品

用户不用竞品的核心理由应该是：

- 竞品偏工具，需要用户自己操作。
- 竞品模板不够垂直。
- 竞品不够懂中文社交平台审美。
- 竞品不能直接给用户一个可发布的结果。
- 即变更像是「选案例，套自己」，而不是「自己修图」。

### 可能的差异点

- 男生变帅展示面。
- 中文小红书写真。
- 头像 / 封面高转化模板。
- 热点玩法商店。
- 低价快速生成。
- 更适合普通人的社交展示结果。
- 面向具体用途的模板包装，而不是泛泛的 AI 生图能力。

## 4. 第一版 MVP

### MVP 验证什么

MVP 验证用户是否愿意完成交易闭环：

- 上传图片
- 选择模板
- 生成结果
- 保存分享
- 为结果付费

技术可行不是核心，交易闭环可行才是核心。

### 第一版必须有什么

第一版必须包含：

- 落地页或首页
- 玩法列表
- 50 个模板
- 图片上传
- 生成任务
- 结果页
- 下载 / 保存
- 简单付费或点数
- 基础数据统计

### 后台需要什么

第一版后台必须支持：

- 模板上下架
- Prompt / Workflow 配置
- 案例图配置
- 价格配置
- 排序配置
- 简单数据统计

后台不需要一开始做成完整运营平台，先满足模板配置、生成任务管理和基础统计即可。

### 是否要登录

需要登录，但不要在用户刚进入产品时强制登录。

推荐策略：

- 浏览模板不需要登录。
- 上传图片、领取免费次数、开始生成、保存结果时再触发登录。
- 登录主要用于防刷、记录生成任务、绑定免费权益和付费权益。

### 是否先付费后生成

第一阶段更适合免费或低价试生成，再对高清、去水印、点数包收费。

原因是用户对 AI 结果不确定，如果先付费后生成，转化阻力会更高。

推荐策略：

- 新用户赠送少量免费次数。
- 邀请好友获得额外次数。
- 单次生成按积分消耗。
- 高清下载、去水印、多次重生成作为付费权益。

## 5. 流量从哪里来

### 当前是否想清楚流量

第一阶段流量策略是全力押注微信小程序，利用微信的社交基础和传播属性。

前期可以设计：

- 新用户免费试用次数。
- 邀请好友获得生成次数。
- 分享结果获得额外权益。
- 朋友圈和社群自然传播。

### 第一渠道建议

第一阶段渠道优先级：

1. 小红书
2. 抖音
3. 朋友圈 / 社群
4. 闲鱼

SEO 可以作为长期项，但不适合作为第一验证渠道。

### 小红书宣传方案

小红书适合发布：

- 前后对比
- 头像案例
- 写真案例
- 展示面案例
- AI 变帅 / 变好看玩法
- 小红书封面人物图案例

重点观察：

- 点击
- 收藏
- 私信
- 引流
- 上传
- 付费

### 闲鱼宣传方案

闲鱼可以作为低价付费测试渠道。

第一阶段不一定完全自动化，可以先人工或半自动交付，验证用户是否愿意为具体图片效果付费。

### 第一批用户目标

第一阶段先拿到 50-100 个真实访问、咨询或试用用户。

不要一开始追求大流量，先证明有人愿意用、愿意上传、愿意保存、愿意付费。

## 6. 商业模式与成本

### 成本与模型策略

产品核心依托高质量图像编辑模型的真实感和编辑能力，同时利用较低的生成成本形成利润空间。

当前假设单张图片成本约 0.02-0.05 元，最高不到 0.1 元。单次结果售价可以测试 0.5-9.9 元区间，部分模板和效果可以绑定会员或点数权益。

架构上需要保持请求抽象统一：

- 一个生成请求包含内置提示词、用户图片、尺寸、比例等信息。
- 尺寸和比例是否开放给用户，可以后续配置。
- 后端可以维护模型源头矩阵和优先级。
- 如果一个源头失败，同一个请求可以切到下一个源头继续生成。
- 生成请求只有一个，但承接它的模型源头可以有多个。

这样可以提升生成成功率，并避免业务层过度绑定单一模型来源。

### 最适合的收费方式

推荐收费方式：

- 免费 / 低价试生成
- 高清下载
- 去水印
- 点数包
- 部分高质量模板会员可用

先让用户看到结果，再让用户为更高质量、更完整权益付费。

### 是否适合订阅

订阅可以保留为后续能力，但第一阶段不应强依赖订阅。

除非后面证明用户高频复购，否则订阅会显得过重。第一阶段优先验证点数包、单次权益和高清下载。

### 免费策略怎么定

可以给少量免费次数，但必须防刷。

免费额度不能无限给，否则生成类产品很容易亏钱。

推荐免费策略：

- 新用户少量免费次数。
- 邀请奖励免费次数。
- 失败任务自动返还点数。
- 免费结果可以带水印或限制清晰度。

### 定价需要算什么

核心公式：

单次毛利 = 单次售价 - 模型成本 - 运营成本

策略：

- 用户没有拿到结果时必须退款或返还点数。
- 失败任务不应该消耗用户权益。
- 高成本模板需要单独定价或限制免费次数。

## 7. 产品形态与市场选择

### 第一版做什么形态

第一版优先做微信小程序。

被动增长依赖用户分享和邀请裂变，主动增长主要走小红书、抖音和闲鱼引流。

Web 第一阶段可作为官网、投流承接页和管理后台，不作为主要 C 端生成入口。

后续如果小程序验证成立，再考虑：

- App
- Web C 端
- 海外版本
- 多语言版本

## 8. 运营系统

### 模板怎么来

模板来源包括：

- 热点
- 竞品
- 小红书爆款
- 抖音爆款
- 节日节点
- 用户反馈
- 高转化模板的相似扩展

### 每个模板必须有什么

每个模板必须包含：

- 封面
- 标题
- 案例图
- 用途说明
- Prompt / Workflow
- 价格
- 风险判断
- 排序权重
- 上下架状态

Prompt / Workflow 只面向内部配置，不直接展示给用户。

### 第一版是否要全自动运营

第一版不要做全自动运营。

先人工或半自动跑出有效模板，再考虑自动化。过早自动化容易把复杂度投入到没有验证过的方向上。

### 后续需要决定的问题

- 每周上新节奏。
- 案例图来源。
- 是否展示用户作品。
- 是否追热点。
- 是否建立模板自动生产 Agent 系统。

模板自动生产 Agent 系统值得提前思考，但不应该成为第一版上线阻塞项。第一阶段先证明哪些模板真的有效。

## 9. 合规与风控

### 这个方向风险高吗

风险高。

人物转换、人脸、写真、换脸、擦边内容都天然存在合规和平台风控风险。

### 第一版风控原则

第一版风控原则：

- 固定模板。
- 不开放自由 Prompt。
- 不做明星脸。
- 不做未成年人相关模板。
- 不做强换脸。
- 不做高风险擦边。
- 不使用「无痕换脸」「明星脸」「想变谁就变谁」「真人替换」等高风险表达。

### 用户上传图片怎么处理

需要明确提示用户：

- 用户必须拥有上传图片的使用权。
- 平台会按隐私政策处理用户图片。
- 图片会进行必要的加密、存储和清理。
- 用户可以删除自己的生成记录或图片资源。

建议策略：

- 免费用户图片保存 7 天。
- 会员用户在会员期间可长期保存。
- 用户主动删除后，业务侧应尽快清理对应资源。

### 是否需要 AI 生成标识

国内需要考虑 AI 生成标识。

结论已经收敛为后端化方案，详见 `docs/即变_AI生成标识后端化方案.md`。

第一版采用“内容显式标识 + 文件元数据隐式标识”：

- 结果图片文件本体添加清晰可见的“AI生成”或“人工智能生成合成”文字标识。
- 结果图片文件元数据写入 `AIGC` 隐式标识，记录生成合成属性、服务提供者和内容编号。
- 会员权益只能去品牌水印，不应去除必要的 AI 生成标识。
- 数字水印可作为后续增强项，但不能替代文件元数据隐式标识。

### 还需要决定的问题

- 图片具体保存多久。
- 用户是否可以发布到社区。
- 是否接入内容审核服务。
- 是否需要人工审核高风险模板。
- 隐私政策和用户协议怎么写。
- AI 生成标识后端化的具体排期和验收。
